Indexed Ignore Matching
======================

Author-facing scope and optimization guidance belongs in
linkgit:gitignore[5]. This document describes the internal index.

Ranked matching
--------------

Each pattern list retains its original ordered array. A private index
maps unescaped literal basenames and base-normalized literal pathnames to
the greatest matching array ordinal, separately for directory-only and
unrestricted rules. Entries retain the original `path_pattern` pointer,
including sign and source provenance. Ordinals, not source line numbers,
determine order; command-line patterns can have negative source numbers.

A query combines basename and pathname candidates, resolving the entry
type only when a competitive directory-only candidate requires it. It
then examines a compact reverse-ordered vector of general-pattern ordinals
until one matches or no remaining ordinal can beat the indexed candidate.
The longest name has no special precedence. Index misses are queries too.

Slash-free `*literal` suffixes use a reversed byte trie. Each terminal
retains separate greatest ordinals for unrestricted and directory-only
rules. Queries visit all applicable terminals, merging by ordinal rather
than suffix length. An empty suffix (`*`) is a root terminal. Compact
child/sibling indices avoid a full byte-sized fanout array per node and
remain valid when the node array grows.

A forward trie indexes literal pathname prefixes ending in `/**`.
Normalized keys include the terminating slash, so the directory itself
and similarly named siblings do not match. Base prefixes are included.
Terminal ranks merge with both literal and suffix candidates, preserving
alternating signs and directory-only variants. Wildcard prefixes and
intermediate `**` components remain in the general vector.

Lists are not merged. Source precedence remains in
`last_matching_pattern_from_lists()`, and `prep_exclude()` still prevents
descendant rules from overriding an excluded parent. Shared non-cone
pattern-list matching can use the index without contributing ignore
telemetry; sparse-checkout cone hashmaps are unchanged.

Ownership and admission
-----------------------

The index belongs to its pattern list. It owns normalized pathname keys
and fallback ordinals, but borrows literal basename keys from patterns.
It owns neither patterns nor their bases. Append invalidates the index;
clear frees it before freeing patterns. No index entry retains the address
of its containing list, which can move when an exclude group grows.
An indexed winner refreshes its original pattern's source-list pointer
before returning it: that back-reference may predate a group-array move.
The deep-stack regression checks verbose provenance across growth and
subsequent stack pop/reload.

Construction is lazy and requires at least 64 supported rules. A conservative
preflight estimate includes entries, keys, fallback ordinals, and hashmap
bucket overhead; estimates above 8 MiB per list retain the legacy scan.
Tiny and general-only lists retain the scan. A supported-fraction cutoff
was rejected because it regressed repeated mixed misses: having many
general rules does not by itself disable a reusable supported subset.
Trie estimates charge two nodes per key byte to account for array growth
and do not assume that keys share prefixes.
The `index-bytes` Trace2 counter sums constructed index payloads, including
owned keys, allocated trie capacity, hashmap buckets, and fallback vectors. It
excludes borrowed patterns and allocator metadata, and is not peak RSS;
reloading a list contributes its new construction again.
Refused construction is remembered until invalidation. These internal
limits are admission heuristics, not user-visible pattern requirements.
Case-insensitive matching also retains the legacy scan until its equality
and normalization semantics are proven for an indexed representation.

One-query and repeated-query measurements retain the 64-rule minimum:
construction is near process-startup cost at that size, while repeated
restricted misses already benefit. The original 4 MiB estimate rejected
8,000 suffix rules whose actual compact payload is much smaller; the
8 MiB estimate admits that workload while keeping a finite preflight bound.
`GIT_TEST_IGNORE_INDEX=0` forces the legacy matcher for differential tests.

Tracing
-------

When Trace2 is enabled, the directory context accumulates three counters
and emits one repository-attributed `ignore` summary before `dir_clear()`:

* `fast-path`: list queries which actually consult an index, including misses.
* `slow-fallback`: list queries which examine at least one general or legacy rule.
* `fallback-patterns-tested`: rules actually examined, including type rejection.

A hybrid query contributes to both query counters. Rank-skipped rules
contribute to neither fallback counter. Tests in `t/lib-ignore.sh` require
singular decimal values, explicit zeros for unused algorithms, and positive
work for algorithms claimed to have run. Missing or duplicate summaries,
cache hits and pruned paths cannot demonstrate fast-path execution.
